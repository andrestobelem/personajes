**Investigación: entornos gráficos open source para personajes autónomos**

Fecha de consulta: **14 de octubre de 2026**. Estado: investigación documental y de código; **no se ha elegido ni adoptado un stack**.

Hay bases open source utilizables para observar personajes que se mueven y conversan. La candidata inicial para este proyecto es **AI Town**, mientras que **Smallville / Generative Agents** aporta la referencia cognitiva más cercana y **AgentSociety 2** merece evaluación si pesan más el registro experimental, la intervención y la escala. Ninguna de las tres resuelve por sí sola una obra teatral con dirección dramática, biografías extensas, conocimiento estrictamente limitado y evolución inspeccionable de objetivos.

La revisión empleó repositorios oficiales, documentación y la publicación original de Generative Agents. Se leyeron implementaciones de interfaz, memoria, percepción y planificación; no se instalaron ni ejecutaron las plataformas y no se comprobó una sesión viva. Por tanto, «disponible» significa que existe documentación o código correspondiente, no una certificación de funcionamiento en la máquina del proyecto. Las fechas y commits son observaciones de las ramas consultadas, no garantías de mantenimiento futuro. Los enlaces a `main` pueden cambiar; los commits de referencia quedan registrados abajo.

El proyecto busca fichas y biografías profundas, recuerdos subjetivos, objetivos propios, modos de hablar diferentes y percepción limitada. El usuario quiere observar movimientos, conversaciones y cambios en relaciones, memorias y objetivos; además, el mundo necesita tiempo ficticio, día/noche, rutinas corporales y una estructura dramática bajo un director que emite metaindicaciones. La intención arquitectónica es un dominio de objetos compuesto, con mensajes también representados como objetos y sin herencia en el dominio.

**AI Town: la base más directa para ver personajes vivir y hablar.**

El repositorio se define como un kit desplegable y extensible con licencia MIT. Utiliza JavaScript/TypeScript, Convex para estado, motor y búsqueda vectorial, y PixiJS para renderizado. Documenta despliegue convencional con Convex y una alternativa Docker Compose con Convex autohospedado. Puede emplear Ollama local o proveedores de modelos configurados. Los personajes, descripciones y sprites se editan en datos, y los mapas pueden prepararse con Tiled. Es una base de desarrollo, no una herramienta terminada de autoría teatral. [Repositorio y despliegue](https://github.com/a16z-infra/ai-town).

La interfaz solicitada sí tiene una implementación: seleccionar un agente permite ver descripción, actividad y conversación actual; si está libre, se muestra la conversación anterior. El componente de mensajes presenta autor, texto, fecha y eventos de participación. Se pueden observar conversaciones entre agentes sin intervenir como personaje. No equivale a un explorador completo de todas las conversaciones históricas: el panel selecciona conversación activa o anterior. [Panel de personaje](https://github.com/a16z-infra/ai-town/blob/main/src/components/PlayerDetails.tsx), [mensajes visibles](https://github.com/a16z-infra/ai-town/blob/main/src/components/Messages.tsx).

Existe memoria subjetiva en el backend. Al terminar una conversación, cada agente produce un resumen desde su perspectiva, incluida su valoración de la interacción. Se almacena con importancia y embedding, se recupera mediante relevancia, recencia e importancia, y se ejecuta reflexión sobre recuerdos. Es una base para recuerdos diferentes de un mismo encuentro. Sin embargo, no se encontró en los componentes examinados un inspector dedicado de recuerdos, inferencias, objetivos o evolución de relaciones. Habría que añadir esa interfaz; el dashboard técnico de base de datos no reemplaza un inspector narrativo. [Memoria implementada](https://github.com/a16z-infra/ai-town/blob/main/convex/agent/memory.ts).

El motor resuelve desplazamiento hacia destinos, replanteamiento ante colisiones y acercamiento antes de conversar. Su modelo documentado limita cada conversación a **dos participantes**. Tiene clases de mundo, jugador, conversación y agente, y entradas procesadas por el motor para modificar estado. Esto favorece conectar un dominio independiente, aunque el motor usa herencia: `Game` deriva de una abstracción del motor. No satisface literalmente una prohibición de herencia en todo el sistema. [Arquitectura](https://github.com/a16z-infra/ai-town/blob/main/ARCHITECTURE.md).

La decisión del agente recibe el mapa y los demás personajes disponibles del mundo, sin filtro de visión en ese punto. Para garantizar que un personaje solo sabe lo que pudo percibir habría que introducir una frontera explícita de observación. Tampoco se verificó un sistema completo de objetivos persistentes con prioridades, conflictos y seguimiento. Personalidad, actividades y recuerdos no bastan para atribuirle esa capacidad. [Bucle del agente](https://github.com/a16z-infra/ai-town/blob/main/convex/aiTown/agent.ts).

AI Town documenta congelación manual y pausa automática tras cinco minutos de inactividad. Eso no demuestra un ciclo día/noche ni sueño, cansancio o fisiología circadiana. Hay usos del reloj real en memorias y actividades, por lo que un tiempo ficticio acelerable exige revisarlos. El costo combina inferencia, embeddings e infraestructura; usar un modelo local cambia costos de API por recursos y latencia locales. [Pausa y configuración](https://github.com/a16z-infra/ai-town#customize-your-own-simulation).

**Smallville / Generative Agents: la referencia cognitiva más cercana.**

El trabajo original presenta 25 personajes que observan, recuerdan, reflexionan, planifican y reorganizan actividades. Incluye difusión de información, formación de relaciones y coordinación de una fiesta a partir de una intención inicial. Es evidencia de investigación sobre comportamiento emergente, no de control dramático sostenido ni fidelidad exhaustiva a una biografía. El propio trabajo describe errores de recuperación, recuerdos adornados y tendencia a expresiones excesivamente formales. [Publicación original](https://arxiv.org/html/2304.03442v2).

La percepción limitada está implementada: radio de visión, prioridad por distancia, atención acotada y eventos de la misma arena. El agente construye memoria espacial de lo observado. Esto es más cercano a personajes que desconocen lo sucedido fuera de su alcance que entregarles el estado global. [Módulo de percepción](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/perceive.py).

Su inspector muestra personalidad, estilo de vida, visión, atención, agenda diaria, acción actual, recuerdos de eventos, conversaciones completas y pensamientos con referencias a evidencia. La demo muestra acción, ubicación y conversación actual, con acceso a detalles. Esos componentes ya existen. [Inspector](https://github.com/joonspk-research/generative_agents/blob/main/environment/frontend_server/templates/persona_state/persona_state.html), [interfaz de la demo](https://github.com/joonspk-research/generative_agents/blob/main/environment/frontend_server/templates/demo/demo.html).

Hay un límite importante para estudiar evolución: el controlador del inspector recibe un número de paso, pero lee los archivos de memoria guardados sin filtrar contenidos por ese paso. No debe describirse como una máquina del tiempo de estados mentales. Permite inspeccionar memoria guardada; recuperar exactamente lo que cada personaje creía en cualquier instante requiere ampliar el registro. [Controlador](https://github.com/joonspk-research/generative_agents/blob/main/environment/frontend_server/translator/views.py).

El repositorio ofrece bases de tres y 25 agentes, carga de historias iniciales y ejecución por pasos de diez segundos simulados. Permite guardar, continuar y reproducir. Declara Apache 2.0 y combina backend Python con Django; la interfaz usa Phaser. La demo se identifica expresamente como reproducción precalculada. Cambiar nombres, población y escenarios puede requerir editar datos y mapa. [Repositorio y operación](https://github.com/joonspk-research/generative_agents).

Su antigüedad técnica pesa: las dependencias fijan Django 2.2 y el SDK OpenAI 0.27. No se debe asumir que las instrucciones históricas funcionen hoy sin adaptación. La planificación contempla despertar, agendas de 24 horas y acciones de dormir; no demuestra un modelo fisiológico circadiano ni iluminación visual día/noche. El costo aumenta con las llamadas de planificación, percepción, valoración, reflexión y diálogo: no se estimaron importes ni rendimiento. [Dependencias](https://github.com/joonspk-research/generative_agents/blob/main/requirements.txt), [planificación diaria](https://github.com/joonspk-research/generative_agents/blob/main/reverie/backend_server/persona/cognitive_modules/plan.py).

**AgentSociety: separar la ciudad legacy de la plataforma actual.**

El repositorio recomienda AgentSociety 2 y conserva AgentSociety 1.x como simulador urbano legacy. La documentación consultada identifica v2.9.3. El proyecto declara Apache 2.0 con una excepción explícita para `packages/agentsociety/commercial`: no debe presentarse todo el monorepo como uniformemente licenciado. La portada del frontend contiene una insignia MIT, mientras remite a la licencia raíz; esa discrepancia no se resolvió en esta investigación. [Repositorio y versiones](https://github.com/tsinghua-fib-lab/AgentSociety), [licencia raíz](https://github.com/tsinghua-fib-lab/AgentSociety/blob/main/LICENSE), [README del frontend](https://github.com/tsinghua-fib-lab/AgentSociety/blob/main/frontend/README.md).

La documentación de v1 confirma una interfaz para trayectorias, cambios de estado, actividad interna y diálogos entre agentes, además de perfiles y experimentos. El frontend actual contiene un mapa Deck.gl/Mapbox con iconos o puntos seleccionables. Sirve para movilidad y distribuciones; no se encontró una puesta en escena con avatares 3D actuando o interiores teatrales animados. Que Mapbox pueda representar un mapa con volumen no demuestra una simulación corporal 3D. [Interfaz documentada v1](https://agentsociety.readthedocs.io/en/latest/01-get-started/04-webui.html), [renderizado](https://github.com/tsinghua-fib-lab/AgentSociety/blob/main/frontend/src/pages/Replay/Deck.tsx).

El panel de inspección muestra perfil, acción y estado actuales, e historial de acciones. Otro panel representa diálogos propios, de otros agentes y con el usuario. Hay avance, retroceso, velocidad y modos replay/live. El botón de pausa examinado detiene la reproducción del visor; ese código no demuestra suspensión de inferencia en el backend. La compatibilidad integral de estos paneles con un experimento v2 concreto queda pendiente de ejecución. [Estado](https://github.com/tsinghua-fib-lab/AgentSociety/blob/main/frontend/src/pages/Replay/LeftPanel.tsx), [diálogos](https://github.com/tsinghua-fib-lab/AgentSociety/blob/main/frontend/src/pages/Replay/ChatBox.tsx), [reproductor](https://github.com/tsinghua-fib-lab/AgentSociety/blob/main/frontend/src/pages/Replay/TimelinePlayer.tsx).

AgentSociety 2 proporciona `PersonAgent`, memoria persistente, memoria episódica recuperable, tareas y archivos de emoción, intención y planificación. Los agentes reconstruyen estado desde workspaces y se ejecutan mediante Ray. Existe herencia explícita `AgentBase → PersonAgent`, aunque las capacidades se amplían mediante skills y módulos. Facilita composición, pero no cumple una prohibición absoluta de herencia dentro del framework. Su enfoque es un laboratorio extensible, no un editor de ficción. [Modelo de agentes](https://agentsociety2.readthedocs.io/en/latest/agents.html).

La API distingue consultas de observación de intervenciones que modifican agente o entorno. Permite pasos con duración definida, replay y recuperación tras interrupciones. Es un apoyo para un director que actúe entre pasos, pero habría que definir la diferencia entre indicación escénica, acontecimiento y recuerdo: la API no aporta esa semántica teatral. [Interacción](https://agentsociety2.readthedocs.io/en/latest/interaction.html), [recuperación](https://agentsociety2.readthedocs.io/en/latest/).

La skill incorporada `daily-guidance` construye una agenda, deriva del reloj su segmento actual e incluye deterioro de necesidades y revisión del plan. Es una base para rutinas, sin demostrar fisiología circadiana completa. v2 necesita Python 3.11+, servicios de modelos y Ray; su web agrega React/Vite y FastAPI. El costo depende de población, pasos y rondas de razonamiento, además de infraestructura. [Rutinas](https://agentsociety2.readthedocs.io/en/latest/agent_skills.html), [instalación](https://agentsociety2.readthedocs.io/en/latest/installation.html).

La recomendación queda condicionada a qué parte debe estar resuelta desde el inicio:

- **Evaluar AI Town primero** si prima una escena 2D comprensible, personajes personalizados y conversaciones observables. Quedan percepción estricta, inspector profundo, objetivos, relaciones, tiempo ficticio y dirección.
- **Usar Smallville como referencia o prueba comparativa** si priman memoria, reflexión, percepción y agenda. Adoptarlo como base supone modernización técnica y mejor registro temporal.
- **Evaluar AgentSociety 2 primero** si prima comparar ejecuciones, intervenir y revisar trazas, aceptando adaptar considerablemente la presentación escénica.

Para preservar el dominio OO por composición, conviene evaluar estas plataformas como infraestructura periférica. Personaje, percepción, recuerdo, objetivo, relación, reloj y mensajes pueden pertenecer a un dominio propio; el entorno visual recibe movimientos y diálogos y entrega observaciones permitidas. Eso es una propuesta de diseño, no una capacidad suministrada. No hay una elección de lenguaje, motor, proveedor o arquitectura final en este documento.

Las brechas comunes a verificar antes de una decisión son: una biografía extensa que siga influyendo con el tiempo; recuerdos distintos y trazables de un mismo acontecimiento; desconocimiento efectivo de hechos no percibidos; objetivos persistentes que cambien con causas observables; voces diferentes; dirección sin convertir metaindicaciones en conocimiento del personaje; y evolución temporal consultable sin confundir replay visual con estado mental histórico. Una escena breve de pocos personajes serviría para evaluar esas propiedades, si posteriormente se autoriza una prueba. Esta investigación no inició esa implementación.
