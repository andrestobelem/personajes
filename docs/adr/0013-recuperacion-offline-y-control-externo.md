# ADR 0013 — Recuperar offline con control durable fuera del directorio sustituido

Recuperar el host completo conserva corridas, memorias y sesiones Pi de la misma raíz y lineage; exige acreditar igualdad del estado recuperable, porque compartir lineage o snapshot no permite descartar cambios posteriores de configuración, voces, presupuesto o subjetividad. Se compara esquema y contenido normalizados de journal e ICM —incluido WAL— y archivos registrados, excluyendo únicamente administración identificada de backup/restore que se preserva explícitamente. Corrupción, tablas y archivos desconocidos bloquean; no equivalen a un host vacío.

El job, la confirmación y sus recibos viven en un directorio hermano del host. Tras drenar solicitudes y cerrar todos los servicios y handles, un gate externo protege staging, conservación del original e intercambio de directorios; se registran fases, identidades, hashes y fsync para reconciliar caídas sin adivinar. Se elige este control externo en vez de guardar el único recibo en el journal que se reemplaza, y el intercambio completo en vez de copiar sobre bases abiertas. El coste son espacio adicional, una interrupción operativa y recuperación explícita de fases ambiguas. El HTTP de control permanece disponible; la GUI consulta la misma operación y el éxito sólo se registra después de reabrir y verificar.

La reanudación tras una caída exige operación conocida y, si existe un gate abandonado, nonce diagnosticado y prueba de ausencia del proceso. Leer el estado no limpia locks ni reanuda. Se mantienen credenciales actuales, backups y recibos administrativos posteriores; las sesiones de interfaz se invalidan y las sesiones Pi conservan sus bytes y leaves. El alcance actual son backups locales registrados de la misma raíz canónica; portabilidad e importación externa permanecen separadas.
