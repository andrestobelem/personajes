# Revisión, reformulación y publicación

## Versión revisada

Cada intento conserva un ID base `prop-<turno>-<slug>` y agrega una versión `v1`, `v2`… dentro del historial de propuestas del actor. Una versión entregada a revisión es inmutable; corregirla exige otra versión. La decisión de permitir se refiere al contenido exacto, no a cualquier texto posterior con el mismo ID.

Toda emisión comunicativa de un actor —respuesta, intervención espontánea o señal no verbal— se revisa antes de hacerse observable. La etapa 03 tiene dos responsabilidades: el Regidor admite canal, capacidad y autoridad; el Continuista evalúa la respuesta por conocimiento, continuidad e identidad. Una acción sin contenido comunicativo y una entrada humana de interlocución no se someten a una voz de personaje inventada: se registra que la revisión de respuesta no aplica, manteniendo el control de autoridad y las reglas del escenario.

## Transiciones

| Resultado de controles | Siguiente operación | Publicación |
|---|---|---|
| Regidor admite y Continuista permite la versión exacta, o no aplica revisión comunicativa | Resolución de Escenario | Sólo después de un evento confirmado y entrega efectiva |
| Continuista pide reformular | El mismo actor vuelve a etapa 02 y entrega otra versión | Ninguna mientras se revisa |
| Regidor o Continuista rechaza | Cierre técnico sin evento para esa propuesta | Ninguna; el sistema no inventa palabras alternativas |
| Revisión incompleta, ausente o referida a otra versión | Mantener etapa 03 pendiente y completar entradas | Ninguna |

El coordinador reúne la devolución técnica mínima en `personajes/<slug>/output/revision.md`. El actor lee sólo la devolución correspondiente a su intento. El archivo no es una observación del escenario y no se copia a memoria como vivencia, orden de una autoridad ficticia o cambio de reglas. No se incluye una ubicación secreta ni una respuesta prefabricada para «corregir» una filtración.

## Reintentos

Una revisión no reserva un evento. Reformular conserva el ID base y no reejecuta acciones anteriores. Se permiten hasta dos reformulaciones automáticas por intento —tres versiones en total—; si no se alcanza una versión permitida, el coordinador deja la revisión incompleta y registra el motivo, sin publicar ni continuar el bucle indefinidamente. Es un límite inicial del protocolo de este workspace, no una regla de ICM o del canon.

Antes de resolver una versión permitida, Escenario consulta si ese ID base ya tiene un evento preparado o confirmado. Si lo tiene, reanuda o reutiliza ese resultado: no publica una segunda versión como si fuera la primera respuesta. Después de una publicación, una rectificación del personaje es una acción nueva, no una modificación silenciosa de lo pronunciado.

Una aprobación no obliga a hablar: Escenario todavía puede resolver que el canal falla, alguien interrumpe o el destinatario no oye. La observación muestra solamente lo efectivamente confirmado y distribuido. El estado técnico de revisión se muestra por separado y nunca como diálogo.
